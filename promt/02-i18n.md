# 02 — Internationalisation

**Prereqs:** 01.
**Owns:** `lib/i18n/`, `components/providers/i18n-provider.tsx`.

---

Three languages: **fr** (default), **en**, **ar** (RTL). English is canonical.

**The guarantee that makes this survive 30 modules:** the `Dictionary` type is
derived from the *English* dictionary, and the French and Arabic dictionaries are
typed as `Dictionary`. So a key added to `en` is a **compile error** until `fr`
and `ar` supply it. Build it that way and never weaken it.

**`lib/i18n/config.ts`** — `LOCALES = ["fr","en","ar"] as const`, `DEFAULT_LOCALE
= "fr"`, `type Locale`, `isRtl(locale)`.

**`lib/i18n/core/{en,fr,ar}.ts`** — strings that belong to no module:
- `common` — save, cancel, delete, edit, create, search, back, yes, no, none,
  loading, actions, active, inactive, total, all, confirmDelete, noResults…
- `validation` — required, tooShort, tooLong, invalidEmail, invalidUrl,
  invalidDate, invalidNumber, mustBePositive, passwordTooShort, notAnImage,
  imageTooLarge, futureDate, endBeforeStart…
- `errors` — unexpected, notFound, forbidden, conflict, sessionExpired.
- `sections` — one label per `NAV_SECTION`.

**`lib/i18n/dictionaries/{en,fr,ar}.ts`** — assemble core + every module's
namespace. This is one of the four registration points. Two namespaces are
**merged** across modules rather than owned by one: `nav` (from each module's
`nav` named export) and `permissions` (from each module's `permissions` named
export, holding `groups` and `codes`). Everything else is a plain spread, so two
modules claiming the same namespace is a type error right here.

**`lib/i18n/types.ts`** — `export type Dictionary = typeof en`.

**`lib/i18n/server.ts`** — `getLocale()` and `getDictionary()`, both wrapped in
React `cache()`. Locale resolution order: the signed-in user's
`Profile.locale` → the `ui-prefs` cookie → `Accept-Language` → `fr`.

**`lib/i18n/format.ts`** — the only place `Intl` is called:
- `interpolate(template, vars)` for `{placeholder}` slots.
- `formatDate`, `formatDateTime`, `formatTime`, `formatMonth`.
- `formatNumber`, `formatDecimal`.
- `formatAmount(centimes, locale)` and `formatMoney(centimes, currencyCode,
  locale)` — money is stored in centimes as `Int` everywhere; formatting is the
  only place it becomes a decimal. Never `toLocaleString` at a call site.

**`components/providers/i18n-provider.tsx`** — a client provider holding the
dictionary and locale, plus `useT()` returning the dictionary and `useLocale()`.
Client components never import the dictionary files directly.

**RTL.** Set `dir` on `<html>` from the locale. Then: **logical CSS properties
only** — `ms-*`/`me-*`/`ps-*`/`pe-*`, `text-start`/`text-end`, `start-0`/`end-0`.
Never `ml-*`, `pl-*`, `text-left`, `left-0`. Add an ESLint rule or a documented
grep so this is checkable, and say in `AGENTS.md` how to check it.

**Gate:** `npm run typecheck` — then *prove* the guarantee: add a throwaway key
to `en` only, show me the type error, remove it.
